# 用户与权限

## 用户体系

### 用户（User）

| 属性 | 说明 |
|------|------|
| email | 邮箱（登录名） |
| password | 密码 |
| blocked | 是否被封禁 |
| blocked_code | 封禁原因代码 |
| default_group_id | 默认所属用户组 |
| two_factor_secret | 双因素认证密钥 |
| two_factor_enabled | 是否启用双因素认证 |

### 用户认证方式

| 认证方式 | 说明 |
|----------|------|
| JWT (Bearer Token) | 基于 JSON Web Token 的 API 认证，无状态 |
| 2FA (TOTP) | 双因素认证，基于 TOTP（Time-based One-Time Password） |

### 认证配置

**JWT 认证：**
- Access Token：登录获取，有效期 24 小时
- Refresh Token：用于刷新 Access Token，有效期 7 天
- Token 黑名单：注销时将 Token 加入 Redis 黑名单，TTL 等于 Token 剩余有效期
- 所有 API 请求需在 Header 中携带：`Authorization: Bearer <token>`

**双因素认证 (2FA)：**
- 基于 TOTP 算法（兼容 Google Authenticator 等应用）
- 启用后登录需额外输入 6 位验证码
- Secret 存储在用户表中

### 密码重置

密码重置流程通过邮件发送重置链接，记录请求的 IP 地址。

### 访问令牌

用户可以生成个人访问令牌（Personal Access Token），用于长期 API 认证，无需频繁刷新。

## 用户组（UserGroup / Administration）

用户组是 Zero-Life 的多租户单元，也称为"Administration"（管理域）。

| 属性 | 说明 |
|------|------|
| title | 组名称 |
| owned_by | 组所有者用户 ID |
| 默认 | 系统自动为每个新用户创建默认组 |

用户组拥有以下实体的完整数据空间：
- 账户、附件、可用预算
- 账单、预算、分类
- 币种、汇率
- 对象分组、周期统计
- 储蓄罐、定期交易
- 规则、规则组
- 标签、交易组、交易日志
- Webhook

## 组成员（GroupMembership）

| 属性 | 说明 |
|------|------|
| user_id | 用户 |
| user_group_id | 用户组 |
| user_role | 组内角色（UserRoleEnum 枚举值） |

一个用户可以通过多个 GroupMembership 属于多个用户组，在每个组中拥有不同的角色。

## 角色体系

### 全局角色

用户可以拥有全局角色（Role），用于跨用户组的权限控制：

| 角色 | 说明 |
|------|------|
| owner | 站点所有者，拥有所有权限 |
| demo | 演示用户，仅只读权限 |

### 组内角色（UserRole）

组内角色通过 UserRoleEnum 定义，共 21 种：

**只读类：**

| 角色 | 说明 |
|------|------|
| READ_ONLY | 只读权限 |
| READ_BUDGETS | 读取预算 |
| READ_PIGGY_BANKS | 读取储蓄罐 |
| READ_SUBSCRIPTIONS | 读取账单/订阅 |
| READ_RULES | 读取规则 |
| READ_RECURRING | 读取定期交易 |
| READ_WEBHOOKS | 读取 Webhook |
| READ_CURRENCIES | 读取币种 |

**管理类：**

| 角色 | 说明 |
|------|------|
| MANAGE_TRANSACTIONS | 管理交易 |
| MANAGE_META | 管理元数据（分类、标签等） |
| MANAGE_BUDGETS | 管理预算 |
| MANAGE_PIGGY_BANKS | 管理储蓄罐 |
| MANAGE_SUBSCRIPTIONS | 管理账单/订阅 |
| MANAGE_RULES | 管理规则 |
| MANAGE_RECURRING | 管理定期交易 |
| MANAGE_WEBHOOKS | 管理Webhook |
| MANAGE_CURRENCIES | 管理币种 |

**高级类：**

| 角色 | 说明 |
|------|------|
| VIEW_REPORTS | 查看报表 |
| VIEW_MEMBERSHIPS | 查看成员关系 |
| FULL | 完全权限 |
| OWNER | 组所有者 |

### 角色检查逻辑

**hasRole(role)** - 检查全局角色：
- 查询用户是否拥有指定的全局角色

**hasRoleInGroupOrOwner(userGroup, role)** - 检查组内角色（含覆盖）：
- 检查用户在指定组中是否拥有指定角色
- OWNER 和 FULL 角色自动覆盖其他角色检查

**hasSpecificRoleInGroup(userGroup, role)** - 检查组内特定角色（不含覆盖）：
- 严格检查用户是否拥有指定的精确角色

## 邀请用户（InvitedUser）

| 属性 | 说明 |
|------|------|
| user_group_id | 邀请加入的用户组 |
| inviter_id | 发出邀请的用户 |
| email | 被邀请者邮箱 |
| invite_code | 邀请码 |
| expires_at | 邀请过期时间 |
| redeemed | 是否已兑换 |

## 用户偏好（Preference）

| 属性 | 说明 |
|------|------|
| user_id | 用户 |
| name | 偏好名称 |
| data | 偏好数据 |
| user_group_id | 用户组 |

常见偏好设置：
- `currencyPreference` - 默认币种
- `languagePreference` - 界面语言
- `viewRangePreference` - 视图范围
- `fiscalYearStart` - 财年起始月
- `remote_guard_alt_email` - 备用邮箱
- `slack_webhook_url` - Slack Webhook URL
- `pushover_app_token` / `pushover_user_token` - Pushover 配置
- `twoFactorAuthEnabled` - 双因素认证开关
- `twoFactorAuthSecret` - 双因素认证密钥

## 用户封禁

用户可以被封禁，封禁后无法登录：
- `blocked = true` - 封禁状态
- `blocked_code` - 封禁原因代码
