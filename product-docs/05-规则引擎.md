# 规则引擎

## 概述

Zero-Life 提供强大的自动化规则引擎，可以根据预设条件自动对交易执行操作。规则引擎支持严格模式和非严格模式，并集成了表达式语言（Expression Engine）用于动态计算。

## 规则组（RuleGroup）

规则按组组织，每组内的规则按顺序执行。

| 属性 | 说明 |
|------|------|
| title | 规则组名称 |
| description | 规则组描述 |
| order | 执行顺序 |
| is_active | 是否启用 |
| stop_processing | 执行完本组后是否停止后续规则组 |

规则组支持的操作：
- 测试规则组：对已有交易测试规则组效果
- 触发规则组：对已有交易执行规则组
- 按顺序执行组内规则

## 规则（Rule）

| 属性 | 说明 |
|------|------|
| rule_group_id | 所属规则组 |
| title | 规则名称 |
| description | 规则描述 |
| order | 组内执行顺序 |
| is_active | 是否启用 |
| strict | 是否严格模式 |
| stop_processing | 执行完本规则后是否停止 |

每条规则包含：
- 多个触发器（RuleTrigger）：定义匹配条件
- 多个动作（RuleAction）：定义执行操作

### 严格模式 vs 非严格模式

| 模式 | 说明 |
|------|------|
| 严格模式（strict = true） | 所有触发器必须同时满足（AND 逻辑） |
| 非严格模式（strict = false） | 任一触发器满足即可（OR 逻辑） |

## 触发器（RuleTrigger）

| 属性 | 说明 |
|------|------|
| rule_id | 所属规则 |
| trigger_type | 触发器类型 |
| trigger_value | 触发器值 |
| order | 检查顺序 |
| is_active | 是否启用 |
| stop_processing | 匹配后是否停止检查后续触发器 |

### 触发器类型

**账户相关：**
- `from_account_starts` / `from_account_ends` / `from_account_is` / `from_account_contains` - 来源账户匹配
- `to_account_starts` / `to_account_ends` / `to_account_is` / `to_account_contains` - 目标账户匹配
- `account_is` / `account_contains` - 任意账户匹配

**金额相关：**
- `amount_less` / `amount_more` / `amount_is` - 金额比较
- `foreign_amount_less` / `foreign_amount_more` / `foreign_amount_is` - 外币金额比较

**描述相关：**
- `description_starts` / `description_ends` / `description_contains` / `description_is` - 描述匹配

**分类与标签：**
- `category_is` - 分类匹配
- `tag_is` - 标签匹配
- `has_category` / `has_tag` / `has_no_category` / `has_no_tag` - 存在性检查

**日期相关：**
- `date_before` / `date_after` / `date_is` - 日期匹配

**类型相关：**
- `transaction_type` - 交易类型匹配

**备注相关：**
- `notes_contain` / `notes_is` / `notes_empty` / `notes_not_empty` - 备注匹配

**其他：**
- `reconciled` - 已对账
- `has_attachments` - 有附件
- `budget_is` - 预算匹配
- `bill_is` - 账单匹配

**特殊触发器：**
- `user_action` - 用户手动触发（始终为 true）

## 表达式引擎

动作值支持使用表达式语言，实现动态计算。表达式引擎为 Go 自定义实现，支持基本算术运算和变量引用。

### 表达式语法

表达式使用 `=` 前缀标识，例如：
- `=amount*0.1` - 金额的 10%
- `=description` - 引用交易描述
- `=date` - 引用交易日期

### 可用变量

| 变量 | 说明 |
|------|------|
| amount | 交易金额 |
| description | 交易描述 |
| date | 交易日期 |
| source_account | 来源账户名 |
| destination_account | 目标账户名 |
| category | 分类名 |
| budget | 预算名 |
| bill | 账单名 |
| tags | 标签列表 |

## 规则执行流程

```
1. 获取所有活跃的规则组（按 order 排序）
2. 对每个规则组：
   a. 获取组内所有活跃规则（按 order 排序）
   b. 对每条规则：
      i. 检查所有活跃触发器
         - 严格模式：所有触发器都匹配才通过
         - 非严格模式：任一触发器匹配即通过
      ii. 如果规则匹配：
          - 按顺序执行所有活跃动作
          - 如果动作设置了 stop_processing，停止后续动作
      iii. 如果规则设置了 stop_processing，停止后续规则
   c. 如果规则组设置了 stop_processing，停止后续规则组
```

## 规则触发时机

规则可以在以下时机触发：

1. **交易创建时** - 新交易保存后自动触发
2. **交易更新时** - 交易修改后自动触发
3. **手动触发** - 用户手动选择交易并触发规则
4. **规则组测试** - 预览规则效果，不实际修改数据
5. **定期交易创建时** - 定期交易生成新交易时触发
